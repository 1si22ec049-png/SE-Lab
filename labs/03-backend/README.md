# SE-Lab: Lab 03 — Why Do We Need a Backend?

This lab updates the Notes App to send notes to a small Java Spring Boot backend. The backend keeps notes in memory while it is running. It does not use a database.

This folder is the standalone Lab 03 project. Lab 01's in-memory-only app is in [../01-memory/](../01-memory/), and Lab 02's `localStorage` app is in [../02-localstorage/](../02-localstorage/).

## Prerequisites

- Java 17 or newer
- Apache Maven 3.6.3 or newer
- Python 3 (to serve the frontend)

Check that Java and Maven are available in a terminal:

```text
java -version
mvn -version
```

## Run the app

Run each command in a separate terminal, starting from the repository folder:

1. Start the backend:

   ```text
   cd labs\03-backend\backend
   mvn spring-boot:run
   ```

   The API listens at `http://localhost:8080`.

3. In a second terminal, serve this lab's frontend:

   ```text
   cd labs\03-backend
   python -m http.server 5500
   ```

4. Open `http://localhost:5500` in Chrome or Edge.

Stop either server with Ctrl+C in its terminal.

The frontend is served by Python and calls the backend at `http://localhost:8080`. The backend permits cross-origin requests only from the exact development frontend origin `http://localhost:5500`; use that address rather than `127.0.0.1` or a different port. This CORS setting is for local learning, not a production security boundary.

## API endpoints

Notes have a numeric `id` and text. For example, creating a note sends:

```http
POST /api/notes
Content-Type: application/json

{"text":"Learn REST"}
```

The server returns HTTP `201 Created` and the created note (the ID is generated by the server):

```json
{"id":1,"text":"Learn REST"}
```

Fetch all notes with `GET /api/notes`:

```http
GET /api/notes
```

```json
[{"id":1,"text":"Learn REST"}]
```

Delete that note with `DELETE /api/notes/1`. The server returns HTTP `204 No Content`. An empty notes list is returned as `[]`.

You can also try requests in PowerShell:

```powershell
Invoke-RestMethod http://localhost:8080/api/notes
Invoke-RestMethod -Method Post -Uri http://localhost:8080/api/notes -ContentType 'application/json' -Body '{"text":"Learn REST"}'
Invoke-RestMethod -Method Delete -Uri http://localhost:8080/api/notes/1
```

## Inspect requests in browser DevTools

Open DevTools with F12, select the **Network** tab, and filter for **Fetch/XHR**. Add or delete a note and select its request to inspect the URL, method, status, and JSON response. Reloading the page sends a `GET` request to retrieve the list again. If the backend is stopped, the browser shows a failed request.

## Experiments

1. **Share notes between browsers:** Start both servers. In Chrome, create a note. Open `http://localhost:5500` in Edge. The note appears there too because both browsers ask the same running backend for its notes.
2. **Restart loses notes:** Create a note, stop the backend with Ctrl+C, and start it again with `cd backend` followed by `mvn spring-boot:run`. Reload the frontend. The list is empty because restarting cleared the backend's in-memory collection.
3. **Backend offline:** Stop the backend, then try to create a note. Inspect the failed request in DevTools Network and read the error shown in the page. The note cannot be created while the server is unavailable.
4. **Compare storage locations:** Lab 02's `localStorage` stores data in one browser profile, so another browser cannot see it. Lab 03's Java collection lives in the backend process, so browsers can share it while that process runs. Both approaches lose data when their respective storage is cleared or the process restarts; this backend does not save notes to disk.

## Run the API test

From the project folder:

```text
cd backend
mvn test
```

The test uses Spring's mock HTTP requests to create a note, retrieve it, delete it, confirm the list is empty, and verify the allowed frontend origin.
